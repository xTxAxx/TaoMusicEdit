# TaoMusicEdit

视频检测与裁剪工作台：集成了 **detector**（视频颜色检测）与 **trimmer**（高精度视频裁剪）两个模块，
并提供一套完整的 **Web UI** 将二者串联成一条可视化工作流：

- 选择视频 → 调参后点「检测」定位目标颜色帧 → 自动关联为「裁剪」起点 → 一键裁剪输出。

---

## 1. 功能特性

### Web UI（可视化工作流）
- **工作区管理**：输入/浏览工作目录，递归文件树浏览，可按需过滤仅显示视频。
- **输出目录配置**：独立设置裁剪输出目录，并校验可写性。
- **播放器**：流式播放、逐帧（上一帧/下一帧）、精确跳转、检测标记覆盖层；
  支持「设为起点 / 设为终点」捕获当前帧，起点（橙）/ 终点（红）/ 检测帧（绿）
  以不同颜色标注在时间轴与画面。
- **时间轴增强**：进度条叠加音频波峰图形，直观反映音频信号特征；下方水平滚动条
  控制可见时间范围（缩略条有最小宽度限制，防止缩得过小而难以拖动）；悬停进度条或
  滚动条时普通滚轮平移时间轴、按住 Ctrl 滚轮以指针为锚点缩放、双击恢复全览；
  播放头采用细线样式，与起点 / 终点标记视觉统一。
- **区间裁剪**：终点为可选参数——留空（无）= 保留到片尾（原有行为）；设置终点后保留
  `[起点, 终点)` 区间，起点与终点相互独立、方式可各自选择（帧序号 / 时间戳），
  检测命中只自动填入起点、不触碰终点。
- **任务中心**：检测 / 裁剪在后台线程执行，SSE 实时推送进度，播放器下方任务中心按
  「颜色检测 / 视频裁剪」两列展示每个文件的状态与进度；单行支持「中断 / 重试 / 删除」
  （删除仅对已终态任务可用，运行中的任务须先中断），列级「全部中断」一键终止本列
  全部运行任务；重试不与运行中的任务互斥——自动排队并复用「批处理 → 并发数」
  （排队中的重试同样可中断；重试以轮询跟踪状态，进度条 / 日志与首跑一致），
  批量任务结束后折叠为一行摘要，摘要实时统计、随重试 / 删行自动更新。
- **批处理**：批量检测 / 批量裁剪分开执行；文件树支持「全选 / 清空」、
  Ctrl 单选、Shift 区间选择；批处理**文件级并行**（并发数可配置，见侧边栏「批处理与缓存」卡片）、
  逐文件汇报进度，单个文件失败不影响整体；批量裁剪维持以检测结果为起点、无终点（保留到片尾）。
- **参数面板**：数据驱动生成 detector / trimmer 全部可调参数，即时校验与行内错误提示。
- **设置持久化**：工作区、输出目录、检测 / 裁剪面板参数、检测结果缓存配置与批处理
  并发数自动保存到配置文件，重启后自动恢复；裁剪起点 / 终点（start_mode / start_value /
  end_mode / end_value）因视频而异，不随配置保存，启动时默认留空；侧边栏底部提供
  「恢复默认设置」按钮一键还原。
- **检测结果缓存**：检测结果持久化到本地 SQLite（`src/webui/detect_cache.db`），
  刷新页面 / 重启服务后自动匹配，无需重新检测；支持开关、条目上限、
  批量检测时跳过已缓存项、清理失效条目与清空缓存。
- **结果可视化**：检测点标注、目标帧定位、裁剪产物列表。

### detector（视频颜色检测）
基于「反向跳帧 + 局部细化」算法，在视频前 N 秒内定位各检测点颜色同时匹配的**结尾帧**
（检测点默认取四角，数量与坐标均可配置），全程仅解码约 40~50 帧，不整片解码。
详细说明见 [detector/README.md](src/detector/README.md)。

### trimmer（高精度视频裁剪）
基于 FFmpeg，支持按**帧序号**或**时间戳**指定保留起点，并可选指定终点（**区间裁剪**，
保留 `[起点, 终点)` 区间；终点缺省时保留到片尾），默认流复制快速裁剪，可选重编码与 GPU 加速，
支持完整视频 / 无声视频 / 纯音频 / 分离音视频四种输出模式。输出统一先写入
`*.part.*` 临时文件、成功后原子替换为最终文件——中断 / 失败不会残留半成品，
也不会损坏已有输出。详细说明见 [trimmer/README.md](src/trimmer/README.md)。

采用行业标准的 **src/ 布局**：三个功能模块（detector / trimmer / webui）统一放在 `src/` 下，
根目录仅保留启动入口、测试与项目配置。各目录功能定位与文件存放规范详见 [STRUCTURE.md](STRUCTURE.md)。

├── src/                    # 全部源码包
│   ├── detector/           # 视频颜色检测模块（可独立使用）
│   │   ├── cli.py / __main__.py  # 命令行入口

│   ├── trimmer/            # 视频裁剪模块（可独立使用）
│   │   ├── cli.py / __main__.py  # 命令行入口
│   │   ├── pyproject.toml  # 独立打包配置
│   │   ├── core/           # 核心（trimmer/ffmpeg/probe/errors）
│   │   ├── utils/          # 校验、日志

│   └── webui/              # Web UI 后端 + 前端
│       ├── __init__.py     # 包标记（webui 作为包导入）

│       ├── jobs.py         # 异步任务管理器（后台线程 + SSE + 取消）

## 3. 环境要求

- Python 3.8+（本项目在 3.13 下开发验证）
- [FFmpeg](https://ffmpeg.org/)（含 `ffmpeg` 与 `ffprobe`，已加入 PATH）
- Python 依赖：
  - `opencv-python`、`numpy`（detector 使用）
  - `flask`（Web UI 使用，已本地化到 `src/webui/_vendor`，无需额外安装）

```bash
pip install opencv-python numpy
# 如需重新安装本地 Flask：py -m pip install -r src/webui/requirements.txt
```

## 4. 快速开始（统一入口）

在项目根目录运行：

```bash
python run.py        # 或 py run.py
```

启动后终端会打印访问地址，浏览器打开 **http://127.0.0.1:8765/** 即可使用。

可选环境变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `WEBUI_HOST` | `127.0.0.1` | 监听地址 |
| `WEBUI_PORT` | `8765` | 监听端口 |
| `TAOMUSIC_BATCH_WORKERS` | `0` | 批处理并发数兜底值。优先取界面「批处理与缓存」卡片中的并发数（落盘时钳制到 0~16），其次取本变量（按原值使用），都为 0 时取 `min(CPU 核数, 4)` |

> 也可直接运行 `py src\webui\app.py`，效果等同。

## 5. Web UI 使用流程

1. **载入工作区**：在左侧边栏「路径与输出」卡片的「工作目录」行输入或浏览目录 → 点「载入」；
   右侧「文件选择」面板的文件树中展开目录并点击选择视频。
2. **设置输出目录**（可选）：在「路径与输出」卡片的「输出目录」行指定裁剪结果保存位置，
   默认保存到项目根目录。
3. **调整参数**：在侧边栏「颜色检测」与「视频裁剪」卡片中修改各参数，参数变化会自动保存。
4. **检测**：点击播放器控制行中的「检测」按钮执行颜色检测，播放器下方「颜色检测」任务卡片
   显示进度与结果；检测命中后**自动关联到裁剪起点**并在播放器中标注目标帧。
5. **裁剪**：确认起点（可手动修改，或用「设为起点」捕获当前帧）；（可选）设置终点——
   直接输入终点值，或播放定位后点「设为终点」捕获当前帧（终点留空 = 保留到片尾，
   点击终点徽标或把终点方式切回「无」可清除终点）。点击「裁剪」按钮完成裁剪，
   「视频裁剪」任务卡片列出输出文件列表。
6. **设置管理**：修改的参数与工作区/输出目录会自动持久化；侧边栏底部「恢复默认设置」
   可一键还原为出厂默认值。

### 批处理（批量检测 / 批量裁剪）

1. **选择文件**：在右侧「文件选择」面板的文件树中选择要批处理的视频——
   - 单击：单选该文件（同时载入播放器）；
   - `Ctrl` + 单击：切换选中/取消该文件（多选）；
   - `Shift` + 单击：从上次点击处到当前文件**区间选择**；
   - 「全选」：选中当前工作区全部视频文件；「清空」取消所有选择；
   - 工具行「已选 N」实时显示选中数量。
2. **批量检测**：点击「批量检测」按钮，对选中文件并行执行颜色检测（并发数见侧边栏
   「批处理与缓存」卡片），任务卡片实时显示每个文件与整体进度；结束后列出每个文件的检测结果
   （命中帧号 / 时间戳 / 未命中 / 失败原因），结果会自动缓存供批量裁剪使用；
   勾选侧边栏「批处理与缓存」卡片中的「跳过已缓存项」时，已有有效缓存结果的视频
   直接复用缓存、跳过重新检测。
3. **批量裁剪**：批量裁剪始终以每个文件的检测结果作为裁剪起点——
   优先使用本次「批量检测」的结果，其次匹配持久化缓存中的有效结果；
   无有效检测结果的文件会自动标记跳过、不参与裁剪。点击「批量裁剪」按钮
   逐文件执行，结束后列出每个文件的输出文件列表。
4. **中断与任务管理**：任务中心每行的「中断」只停该文件（整批其余文件继续），
   列级「全部中断」一键终止本列全部运行任务（含整个批次）；任务结束后折叠组可展开
   查看逐文件明细，「重试」将该文件作为单文件任务重新执行（多个重试按侧边栏并发数
   自动排队、满额等待，排队中可中断），折叠组摘要随重试 / 删行
   实时更新；「删除」仅移除已终态（成功 / 失败 / 已取消）的条目。

### 参数说明

**Detector**（详见 [detector/README.md](src/detector/README.md)）

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| 目标颜色 | `#F7F10F` | 支持 `#RRGGBB` 或 `R,G,B` |
| 检测点坐标 | `20,20 1900,20 20,1060 1900,1060` | 自定义检测点（坐标成对，数量不限，针对 1920×1080） |
| 置信度阈值 | `0.97` | 匹配阈值 [0,1]，越高越严格 |
| 颜色容差 | `10.0` | RGB 欧氏距离容差，兼容有损编码 |
| 检测点自动缩放 | 开 | 按视频分辨率等比缩放检测点 |
| 检测窗口(秒) | `40` | 只检测视频前 N 秒 |
| 反向跳帧起始(秒) | `35` | 反向抽帧起始时间 |
| 粗扫步长(秒) | `5` | 初始大步长 |
| 细扫步长(秒) | `1` | 细化步长（须 ≤ 粗扫） |
| 帧提取器 | `ffmpeg` | `ffmpeg`（精确）/ `opencv`（回退） |
| GPU 硬解 | `自动` | 解码加速：自动 / 关闭 / d3d11va / dxva2 / cuda / qsv；后端不可用自动回退 CPU 软解 |

**Trimmer**（详见 [trimmer/README.md](src/trimmer/README.md)）

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| 起点方式 | `帧序号` | 帧序号 `-f` / 时间戳 `-t` 二选一 |
| 裁剪起点 | 必填 | 可先「检测」或捕获帧后自动填入 |
| 终点方式 | `无（到片尾）` | 无 / 帧序号 `-F` / 时间戳 `-T`；「无」= 保留到片尾（原有行为） |
| 裁剪终点 | 可选 | 播放定位后点「设为终点」捕获当前帧，或手动输入；须大于起点 |
| 输出文件名后缀 | `_trim` | `input.mp4 → input_trim.mp4` |
| 输出模式 | `完整视频` | 完整 / 无声视频 / 纯音频 / 分离音视频 |
| 覆盖已存在文件 | 关 | 输出已存在时直接覆盖 |
| 重编码 | 关 | 默认流复制（快速）；重编码可精确到帧（区间双端同样适用） |
| GPU 加速 | `自动` | 自动 / 关闭 / 强制 |
| 视频/音频编码器 | 空 | 重编码时指定，留空自动匹配 |

## 6. 配置持久化

- 配置文件：`src/webui/settings.json`（首次保存设置后自动生成）。
- 保存内容：
  - 工作区路径、输出目录；
  - 侧边栏「颜色检测」卡片的 11 项参数（与 `DetectorConfig` 的界面可调字段一一对应）；
  - 侧边栏「视频裁剪」卡片中除起点 / 终点外的 7 项参数
    （suffix / output_mode / force / reencode / hw_accel / video_codec / audio_codec）；
  - 检测结果缓存配置（缓存开关、条目上限、跳过已缓存项）与批处理并发数。
- 不参与持久化：裁剪起点 / 终点（start_mode / start_value / end_mode / end_value）
  因视频而异，启动时默认留空 / 无终点；`DetectorConfig` 中未暴露给界面的字段
  （`reference_resolution`、`ffmpeg_path`、`ffprobe_path`、`log_level` 等）也不落盘。
- 保存时机：任意参数变化、工作区/输出目录变化后 **自动防抖保存**（约 400ms）；
  无需手动操作。
- 启动恢复：应用启动时读取配置文件，自动恢复上次的工作区、输出目录与参数；
  配置不存在或路径失效时回退到项目根目录。
- 恢复默认：侧边栏底部的「恢复默认设置」按钮，删除配置文件并将各分组重置为默认值。

相关接口：

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/api/settings` | GET | 读取当前设置与默认值 |
| `/api/settings` | POST | 保存设置（服务端合并后落盘） |
| `/api/settings/reset` | POST | 恢复默认设置（删除配置文件） |
| `/api/detect-cache` | GET | 查询检测结果缓存（带 `path` 查单个视频，不带则返回全部有效条目） |
| `/api/detect-cache/config` | GET / POST | 读取 / 更新缓存配置（开关、条目上限、跳过已缓存） |
| `/api/detect-cache/prune` | POST | 清理失效条目（源文件已删除 / 已修改 / 结果损坏） |
| `/api/detect-cache/clear` | POST | 清空全部缓存条目 |

### 检测结果缓存（detect_cache）

- 数据文件：`src/webui/detect_cache.db`（SQLite，WAL 模式），单次检测与批量检测完成后自动写入。
- 有效性校验：按文件 mtime + 大小判断，源文件被修改或删除后缓存自动视为失效，不会返回过期结果。
- 自动复用：刷新页面 / 重启服务后，选中视频会自动匹配缓存中的检测结果并填入裁剪起点，
  无需重新检测；「批量裁剪」也会直接复用这些结果。
- 管理入口：侧边栏「批处理与缓存」卡片可开关缓存、设置条目上限（0 表示不限，超出自动淘汰最旧的）、
  刷新统计、清理失效条目或一键清空。

## 7. 模块独立使用

两个模块均可脱离 Web UI 独立通过命令行或 Python API 使用。

### detector

```bash
# 直接运行（推荐，无需安装）
py src\detector\cli.py input1.mp4
# 示例输出: frame=734 time=24.466666666666665
py src\detector\cli.py input1.mp4 --target '#F7F10F' --threshold 0.9
# 模块方式运行（需在 src 目录下执行，或设置 PYTHONPATH=src）
py -m detector input1.mp4 --target '#F7F10F' --threshold 0.9
```

```python
from detector import VideoColorDetector
frame, time = VideoColorDetector().detect("input1.mp4")
print(frame, time)
```

### trimmer

```bash
# 直接运行（推荐，无需安装）
py src\trimmer\cli.py input1.mp4 -f 735 -o out.mp4 -y
py src\trimmer\cli.py input1.mp4 -t 24.5 -r --hw-accel auto
# 区间裁剪：保留 [24.5s, 3600s)
py src\trimmer\cli.py input1.mp4 -t 24.5 -T 3600
# 模块方式运行（需在 src 目录下执行，或设置 PYTHONPATH=src）
py -m trimmer input1.mp4 -t 24.5 -r --hw-accel auto
```

```python
from trimmer import Trimmer, TrimmerConfig
cfg = TrimmerConfig(input_path="input1.mp4", frame=735, output_dir="out", force=True)
result = Trimmer(cfg).run()
print(result.output_files)

# 区间裁剪：保留 [起点, 终点) 区间（终点缺省时保留到片尾）
cfg = TrimmerConfig(input_path="input1.mp4", timestamp=24.9, end_timestamp=3600.0)
result = Trimmer(cfg).run()
```

> 示例中的 `input1.mp4` 是约定的测试素材名（本仓库的实际素材为「编号_标题_*.mp4」
> 命名且不提交）。用实际素材跟练时，把命令中的 `input1.mp4` 换成实际文件名即可。

## 9. 常见问题

- **端口被占用？** 设置 `WEBUI_PORT` 换一个端口，或先结束占用 8765 的进程再启动。
- **点了「检测」/「裁剪」没有反应？** 单个视频的检测 / 裁剪需先在右侧「文件选择」中选中
  并载入视频；裁剪还要求裁剪起点已填写（可先检测自动填入，或点「设为起点」捕获）。
  前置条件不满足时不会发起任务，进度与结果统一显示在播放器下方的任务卡片中。
- **页面样式/脚本不更新？** 本地开发未开 debug 缓存；已为静态资源加版本号，仍异常时按
  `Ctrl+F5` 强制刷新。
- **检测不到目标颜色？** 适当调大「颜色容差」或调低「置信度阈值」以兼容有损编码色偏。
- **裁剪起点/终点不精确？** 流复制模式下起终点会吸附到关键帧；勾选「重编码」可精确到帧
  （区间双端同样适用）。
- **中断后输出目录有残留文件？** 正常不会：裁剪输出统一先写 `*.part.*` 临时文件，
  成功后原子替换为最终文件、中断 / 失败自动清理。仅当进程被强杀等极端情况可能遗留，
  此类文件为不可播放的半成品，可安全删除。
- **FFmpeg 未加入 PATH？** 安装 FFmpeg 并加入 PATH，或通过模块的 `ffmpeg_path` /
  `ffprobe_path` 指定完整路径。
