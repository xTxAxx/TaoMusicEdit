> 状态：已实施（2026-09-07；实施变更见 git 历史，README 已按 §5.5 同步）
> 变更来源：项目需求变更（见 §0.2）
> 关联模块：trimmer（主要改动）、webui（交互与 API）、detector（零改动，仅声明范围边界）

## 0. 需求变更说明

### 0.1 变更背景

前期《复杂视频结构多段处理技术方案调研》探索了多标记检测、结构模板、音频辅助分段等
技术方向。经评审，项目需求调整如下：**检测能力维持现状（仅片头），复杂结构处理改由
「用户手动区间裁剪」承担**。原调研文档由本文档取代，调研中提出的检测层扩展方向
（多标记 / 多色检测、场景切换检测、音频辅助、结构模板）**均不采用**。

### 0.2 需求变更清单

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| R1 | 片头检测功能保持不变 | 现有实现逻辑与参数配置零改动 |
| R2 | 检测范围明确限定为视频片头 | 不包含任何内容片段或片尾的检测功能（范围边界声明） |
| R3 | 新增区间裁剪功能 | 由用户手动选择起始时间点与结束时间点，对音视频文件进行精确裁剪 |
| R4 | 区间裁剪与片头裁剪不冲突 | 片头检测标记出起点后，用户可自行决定是否更改起点、是否添加终点 |

### 0.3 核心设计原则

「不冲突」（R4）的实现方式：**区间裁剪是现有片头裁剪的严格超集**——

1. 终点是**可选参数**：留空时行为与现有版本完全一致（从起点保留到片尾），向后兼容零破坏；
2. **检测与裁剪解耦**：检测只负责提供「建议起点」，终点永远由用户手动提供；
3. 起点与终点是**相互独立**的两组参数：修改、清除互不影响，检测重跑只更新起点。

## 1. 功能说明

### 1.1 功能定义

**区间裁剪**：保留输入文件位于 `[起点, 终点)` 区间内的音视频内容，输出为新文件。

| 参数 | 必填性 | 指定方式 | 说明 |
| --- | --- | --- | --- |
| 起点 | 必填（现状不变） | 帧序号 或 时间戳 | 可来自检测自动填充、手动输入、「设为起点」捕获当前帧 |
| 终点 | **可选（新增）** | 帧序号 或 时间戳 | 手动输入或「设为终点」捕获当前帧；**留空 = 保留到片尾** |

- 起点方式与终点方式可独立选择（如起点用帧序号、终点用时间戳），内部统一换算为时间戳执行。
- 现有四种输出模式（完整 / 无声 / 纯音频 / 分离）、重编码、GPU 加速、输出命名规则
  （`<原名>_trim<扩展名>`）对区间裁剪全部沿用。

### 1.2 用户视角的行为说明

| 场景 | 操作路径 | 结果 |
| --- | --- | --- |
| 片头裁剪（现状，完全保留） | Detect → 起点 → Trim | 保留起点到片尾 |
| 区间裁剪（检测辅助起点） | Detect → 按需改起点 → 手动加终点 → Trim | 输出区间段文件 |
| 区间裁剪（纯手动，不经检测） | 播放定位 → 设为起点 → 定位 → 设为终点 → Trim | 输出区间段文件 |

### 1.3 与片头裁剪的共存设计（R4 详解）

数据流：

```
Detect（片头检测，零改动）
   │  检测命中：自动填入
   ▼
起点参数（可修改 / 可清除，现状能力）
   │                       用户手动（输入 或「设为终点」捕获当前帧）
   ▼                                   ▼
Trim 执行  ◄──── 终点参数（可修改 / 可清除，新增能力，可选）
```

共存规则：

| 规则 | 内容 |
| --- | --- |
| C1 | 检测命中后只自动填充**起点**，**永不自动填充终点**（检测范围仅片头，无片尾信息） |
| C2 | 起点与终点参数相互独立：修改 / 清除终点不影响起点，反之亦然 |
| C3 | 重新执行检测时，按现状规则更新起点，**不触碰终点** |
| C4 | 终点留空时，Trim 行为与现有版本完全一致（兼容基线，验收项 A1） |
| C5 | 起点方式与终点方式可独立选择，内部统一换算 |

## 2. 操作流程

### 2.1 单视频流程（Web UI）

**流程 B：区间裁剪（检测辅助起点）**

1. 载入视频：侧边栏工作区选择视频（现状）；
2. 点击 `Detect`：检测片头结束帧，自动填入起点并在播放器中标注目标帧（现状不变，R1）；
3. （可选）按需修改起点：直接改数值，或播放定位后点「设为起点」捕获当前帧（现状能力）；
4. **（新增）设置终点**：直接输入终点值，或播放定位后点「设为终点」捕获当前帧；
   终点以区别于起点 / 检测标记的颜色标注在播放器时间轴；
5. （可选）清除终点：退化为片头裁剪（现状行为）；
6. 点击 `Trim`：输出区间文件到输出目录，结果面板列出输出文件（现状交互）。

**流程 C：纯手动区间裁剪（不经检测）**

播放定位 → 「设为起点」（或直接输入起点）→ 定位 → 「设为终点」（或直接输入终点）→ `Trim`。
全程无需 Detect，适合任意来源的音视频文件（R3 中「音视频文件」均适用）。

### 2.2 批处理

批量 Trim 维持现状：以检测结果为起点、无终点（保留到片尾）。

**设计边界说明**：检测范围仅限片头（R2），批量场景没有可靠的终点来源；终点本质上是
单视频交互式能力（逐视频人工定位），不适合批处理。此为有意的设计边界，非遗漏。

### 2.3 命令行 / Python API 流程（trimmer 独立使用）

```bash
# 保留 [24.9s, 3600s) 区间
trimmer input.mp4 -t 24.9 -T 3600

# 帧序号方式：保留 [第735帧, 第108000帧)
trimmer input.mp4 -f 735 -F 108000

# 不带终点 = 现状行为（保留到片尾）
trimmer input.mp4 -t 24.9
```

```python
from trimmer import Trimmer, TrimmerConfig

result = Trimmer(TrimmerConfig(
    input_path="input.mp4",
    timestamp=24.9,        # 起点（必填，现状）
    end_timestamp=3600.0,  # 终点（可选，新增）
)).run()
print(result.output_files)
```

## 3. API 接口定义

### 3.1 Python API：`TrimmerConfig` 扩展

新增两个可选字段：

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `end_timestamp` | `float \| None` | `None` | 终点时间戳（秒）；提供时须 > 起点换算时间戳 |
| `end_frame` | `int \| None` | `None` | 终点帧序号（从 1 开始）；提供时须 > 起点帧序号 |

参数校验规则（`VALIDATION_ERROR` 场景扩展）：

| 校验 | 规则 |
| --- | --- |
| 互斥 | `end_timestamp` 与 `end_frame` 不可同时提供（与起点 `timestamp`/`frame` 规则对称） |
| 可缺省 | 两者均缺省 = 保留到片尾（现状行为） |
| 顺序 | 终点（换算后）必须 **>** 起点，否则报错 |
| 范围 | 终点不得超过视频时长 / 总帧数 |
| 组合 | 起点方式与终点方式可不同（帧序号 × 时间戳自由组合，内部统一换算为时间戳） |

### 3.2 CLI：`trimmer` 新增参数

| 参数 | 说明 |
| --- | --- |
| `-T, --end-timestamp SEC` | 终点时间戳（秒，浮点），与 `--end-frame` 二选一，可选 |
| `-F, --end-frame N` | 终点帧序号（从 1 开始），与 `--end-timestamp` 二选一，可选 |

### 3.3 Web UI HTTP API：`POST /api/trim`

请求体新增可选字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `end_mode` | `"frame" \| "timestamp" \| null` | 终点指定方式；`null` / 缺省 = 无终点（到片尾） |
| `end_value` | `number \| null` | 终点值；须与 `end_mode` 同时出现 |

- 响应结构与任务进度推送（SSE）沿用现状，仅输出文件可能为区间段文件；
- 校验失败（`end ≤ start`、超范围、`mode`/`value` 不匹配）返回 400 与行内错误消息；
- **设置持久化**：`end_mode` / `end_value` 与现有 `start_mode` / `start_value` 约定一致，
  因视频而异**不随 `settings.json` 保存**，启动时默认留空。

### 3.4 模块交互（数据流边界）

| 模块 | 变更 | 说明 |
| --- | --- | --- |
| detector | **零改动** | `Detection` 单帧结果 → webui 填起点的现状链路原样保留（R1） |
| trimmer | 新增终点能力 | 起点 / 终点统一在模块内换算与校验，模块可独立使用 |
| webui | 编排扩展 | 检测 → 起点（现状）；终点 → 独立参数组（新增） |
| 检测缓存 | **零改动** | 缓存仍只存片头检测结果（单帧），与终点无关 |

## 4. 参数说明

### 4.1 Web UI 参数面板（Trimmer · 视频裁剪）

新增控件（与现有起点控件对称）：

| 控件 | 类型 | 说明 |
| --- | --- | --- |
| 终点方式 | 下拉：`无（到片尾）` / `帧序号` / `时间戳` | 默认「无」= 现状行为 |
| 裁剪终点 | 数字输入 | 与方式联动校验；终点 ≤ 起点、超范围时行内错误提示 |
| 「设为终点」按钮 | 播放器控制行 | 捕获当前帧为终点（与现有「设为起点」对称） |

播放器表现：终点标记加入现有「检测标记覆盖层」体系，时间轴竖线 + 画面标注，
颜色区别于起点 / 检测标记；提供「清除终点」入口。

### 4.2 检测范围声明（R2）

- detector 的算法、`DetectorConfig`、CLI、检测结果缓存**均无任何变化**；
- 在文档层面明确声明：检测对象为**视频片头部分**（默认前 40 秒窗口，
  `search_window` 可调），**不提供**内容片段检测、片尾检测能力；
- 复杂结构（多首歌、插入内容、片尾等）的处理统一由用户手动区间裁剪完成（R3）。

### 4.3 参数总览（变更后 trimmer 完整参数）

| 参数 | 现状 / 新增 | 说明 |
| --- | --- | --- |
| `timestamp` / `frame` | 现状 | 起点（二选一，必填） |
| `end_timestamp` / `end_frame` | **新增** | 终点（二选一，可选；缺省 = 到片尾） |
| `output_path` / `output_dir` / `suffix` | 现状 | 输出位置与命名（区间裁剪沿用 `_trim` 后缀） |
| `output_mode` | 现状 | 完整 / 无声 / 纯音频 / 分离（区间裁剪全部支持） |
| `reencode` / 编码器 / `hw_accel` | 现状 | 重编码与 GPU 加速（区间裁剪全部支持） |
| `force` | 现状 | 覆盖确认 |

## 5. 实现考量（面向后续实施）

### 5.1 FFmpeg 命令构建

现状：`ffmpeg -ss <start> -i <input> ...`（起点为输入侧选项）。

区间模式：`ffmpeg -ss <start> -to <end> -i <input> ...`

- `-to` 与 `-ss` 同为**输入侧**选项（置于 `-i` 之前），两者均在**输入时间轴**上取
  绝对位置，语义最清晰：起点吸附不影响终点位置；
- 输入侧 `-to` 需要较新版本的 FFmpeg（约 4.4+）；实施时应探测版本，旧版回退为
  输出侧 `-t <end - start>`（兼容回退，精度差异见 §5.2）；
- 输出侧选项（重编码参数、输出模式选择、`-avoid_negative_ts make_zero`）不受影响，沿用现状。

### 5.2 精度语义

| 模式 | 起点精度 | 终点精度 |
| --- | --- | --- |
| 流复制（默认） | 吸附关键帧（现状语义不变） | 输入侧 `-to`：包级截断，接近精确；回退 `-t` 方案：随起点吸附整体前移 |
| 重编码 | 帧精确（现状） | 帧精确 |

- 现有 FAQ「裁剪起点不精确？→ 勾选重编码可精确到帧」的说明对区间双端同样适用；
- 输出区间时长下限保护：流复制双端吸附后区间为空时，明确报错而非输出空文件。

### 5.3 校验与错误处理

- `VALIDATION_ERROR` 错误码扩展：终点 ≤ 起点、终点超范围、`end_timestamp` 与
  `end_frame` 冲突（错误码体系不变，仅新增触发场景）；
- `out_duration` 由 `duration - start` 调整为 `end - start`（影响进度估算与时长展示）；
- VFR 视频：帧序号 ↔ 时间戳换算沿用现有「平均帧率近似」约定，区间端点建议优先时间戳。

### 5.4 测试计划

| 类别 | 内容 |
| --- | --- |
| 单元 | `build_command` 区间模式（含 `-t` 回退分支）、终点校验矩阵（互斥 / 顺序 / 范围 / 组合） |
| 集成 | 合成视频区间输出：重编码断言时长 = `end - start`（误差 ≤ 1 帧）；流复制断言吸附语义内正确 |
| 回归 | 终点缺省路径与现有 71 个 trimmer 用例行为一致（兼容基线 A1） |
| webui | `/api/trim` 终点参数校验、终点留空等价性、检测填充不触碰终点（C3） |

## 6. 验收标准

| 编号 | 标准 |
| --- | --- |
| A1 | 终点缺省时，现有全部测试（detector 86 + trimmer 71）通过，行为零变化（兼容基线） |
| A2 | 重编码区间裁剪：输出时长 = `end - start`，误差 ≤ 1 帧 |
| A3 | 流复制区间裁剪：起点吸附关键帧（现状语义），终点不劣于包级精度 |
| A4 | 终点 ≤ 起点 / 超出范围 / 方式冲突 → `VALIDATION_ERROR`（CLI 退出码）或 400（Web UI） |
| A5 | 检测命中 → 仅自动填充起点；终点不受检测影响；起终点可独立修改 / 清除（C1~C3） |
| A6 | 区间裁剪完整支持四种输出模式、重编码与 GPU 加速 |
| A7 | 批量 Trim 行为与现状一致（起点裁剪到片尾） |
| A8 | detector 模块零改动（R1 / R2 的回归确认） |
